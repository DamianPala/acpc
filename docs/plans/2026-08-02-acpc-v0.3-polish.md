# acpc v0.3: polish the calling surface, for agents and for people

Deferred out of v0.2 (`2026-08-01-acpc-v0.2-daemon.md`).
v0.2 ships the daemon; v0.3 makes it pleasant to call.

## 1. The theme

v0.2 turned out **accidentally good for agents and bad for people**, and neither was designed.

`is_tty = sys.stdin.isatty()` (`cli.py:248`) decides two things at once: the default permission level, and whether the daemon is used at all.
A non-interactive caller gets `read` and the daemon; a person at a terminal gets `prompt` and is routed around the daemon by bypass rule 3.
So the 14x CPU saving lands on the caller who invokes acpc in a loop, and never on the one watching it run.

Both halves need work, and they are not the same work:

- **People** need the daemon to stop being unreachable, and need to see what it decided on their behalf.
- **Agents** need the surface to be predictable and self-describing, so a model can use it correctly from `--help` alone.

## 2. Human path

| # | Item | Note |
|---|------|------|
| 1.1 | Interactive permissions through the daemon | Half-built: the `permission` frame already carries decisions daemon → client. Missing the reverse leg (question, answer). Needs a policy for a caller that exits mid-turn, and a timeout, since a human thinking holds a concurrency slot |
| 1.2 | Decide what an interactive TTY should default to | Today it silently costs the user the daemon. Options: keep and document, hint the flag on stderr, or change the default |
| 1.3 | Surface the daemon in the human's mental model | `daemon status` is the only window into what the daemon thinks; make it reachable without knowing it exists |

## 7. Measurements to keep in mind

Taken 2026-08-02 against a real adapter, one agent:

- **Cancel does not stop generation.** The cancelled turn runs to completion and the session stays busy until it does. A 5000-word request wedged it for 151s. acpc returns 124 immediately and correctly, so this is an adapter property, not a defect to fix here.
- **CPU is the honest metric, not wall clock.** Direct 6,15s CPU vs 0,44s through the daemon, while wall time only halved. Any v0.3 benchmark should say so.
- **Two simultaneous requests stagger by seconds on the direct path too**, where the adapters are separate processes. Timing ratios measure the account, not acpc.
